# 휴대폰 PWA QR 송금 MVP 화면·동선 개선 설계

작성일: 2026-10-14

## 목표

60대 판매자 두 분이 삼성 안드로이드 휴대폰에서 앱처럼 실행하고, 행사 현장에서 최종 판매 금액을 빠르게 입력해 고객에게 송금 QR을 보여주는 MVP를 완성한다. 고객은 주로 40대 중반 이상이며, 본인이 사용하는 국내 은행 앱으로 송금한다.

## 검토한 접근

### 1. 기존 화면의 CSS만 수정

가장 빠르지만 금액 입력, 자동 복귀, 은행 선택, PWA 설치 등 실제 사용 동선의 문제를 해결하지 못한다.

### 2. 기존 정적 TypeScript 구조를 유지하고 화면과 동선을 재설계 — 선택

서버 없는 현재 구조를 유지하면서 판매자와 고객 화면을 모바일 중심으로 다시 구성한다. 개발 범위가 작고 GitHub Pages에 그대로 배포할 수 있으며, 후속 기능을 추가하기도 쉽다.

### 3. React 또는 네이티브 Android 앱으로 재개발

확장성은 높지만 현재 MVP에 비해 개발·설치·유지보수 부담이 크다. 이번 단계에서는 선택하지 않는다.

## 지원 기기와 설치 방식

- 1차 검증 기기: 삼성 안드로이드 휴대폰 2대
- 설치 방식: GitHub Pages에 배포한 PWA를 홈 화면에 설치
- 화면 방향: 휴대폰 세로 화면
- 휴대폰과 태블릿에서 같은 세로 한 줄 구조를 유지할 수 있게 CSS를 작성하되, 태블릿 실기기 검증은 후속 단계로 미룬다.
- 고객은 앱 설치 없이 기본 카메라로 QR을 촬영해 웹 송금 안내 화면을 연다.

## 판매자 동선

### 최초 실행

1. 사용자 1 또는 사용자 2를 한 번 선택한다.
2. 선택 결과를 기기에 저장한다.
3. 이후 실행부터는 판매자 선택을 생략하고 금액 입력 화면으로 바로 이동한다.
4. 판매자 변경은 주 화면이 아닌 설정 메뉴에서만 할 수 있다.

### 금액 입력 화면

- 상단에 받는 분 이름을 가장 크게 표시한다.
- 바로 아래에 은행명과 전체 계좌번호를 최소 18px 글자로 표시한다.
- 현재 입력 금액을 48~72px 크기로 표시한다.
- 금액 아래에 한글 금액을 함께 표시한다. 예: `14,000원`, `일만 사천 원`.
- 화면 내부에 0~9, 지우기, 전체 지우기로 구성된 큰 숫자 키패드를 둔다.
- 입력 범위는 1,000원 이상 500,000원 이하이며 1,000원 단위만 허용한다.
- 마지막 세 자리가 `000`이 아니거나 범위를 벗어나면 QR 생성 버튼을 비활성화하고 짧고 직접적인 안내를 표시한다.
- 제품 선택 기능은 이번 단계에서 추가하지 않는다. 판매자가 계산한 최종 금액만 입력한다.

### QR 화면과 자동 복귀

1. 유효한 금액에서 `QR 만들기`를 누르면 큰 QR, 받는 분 이름, 숫자 금액, 한글 금액을 표시한다.
2. QR 화면을 15초간 유지한다.
3. QR 생성 시점의 판매자·금액·시간을 해당 휴대폰의 로컬 저장소에 자동 기록한다.
4. 15초 후 별도 확인 버튼 없이 금액 입력 화면으로 자동 복귀하고 입력값을 초기화한다.
5. 화면에는 기록 오차에 대한 경고 문구를 표시하지 않는다.
6. 실제 입금 여부는 은행 문자 또는 앱 알림을 판매자가 직접 확인한다. PWA는 문자나 알림 내용을 읽지 않는다.

## 고객 송금 화면

- 상단에 보낼 금액을 가장 크게 표시한다.
- 받는 은행, 예금주, 전체 계좌번호를 명확하게 표시한다.
- 고객이 사용하는 은행을 선택할 수 있도록 큰 은행 버튼을 2열로 표시한다.
- 첫 목록의 순서는 다음과 같다.
  1. NH농협
  2. KB국민
  3. 신한
  4. 우리
  5. 하나
  6. IBK기업
  7. 카카오뱅크
  8. 토스
- 그 아래에 `다른 은행 보기`를 두어 나머지 지원 은행을 펼친다.
- 일반 은행 버튼을 누르면 판매자 계좌번호를 클립보드에 복사하고 선택한 은행 앱 실행을 시도한다.
- 은행 앱에서는 고객이 받는 은행을 선택하고 계좌번호를 붙여넣은 뒤 표시된 금액을 직접 입력한다.
- 토스 버튼은 비공식 송금 딥링크로 받는 은행·계좌·금액 자동 입력을 시도한다.
- 토스 연결이 동작하지 않으면 계좌번호 복사와 수동 송금 안내를 제공한다.
- 어떤 경우에도 웹앱이 송금을 확정하지 않는다. 최종 인증과 송금은 고객의 은행 앱에서 이루어진다.

## 시각·접근성 원칙

- 고대비 실용형 디자인을 사용한다.
- 본문은 22px 이상, 보조 계좌 정보는 18px 이상, 핵심 금액은 48px 이상으로 한다.
- 주요 버튼은 최소 72px 높이, 버튼 사이 간격은 최소 12px로 한다.
- 흰색 또는 매우 밝은 배경, 짙은 글자, 선명한 테두리를 사용한다.
- 상태를 색상만으로 구분하지 않고 글자와 아이콘을 함께 사용한다.
- 한 화면에는 하나의 주요 작업만 둔다.
- 애니메이션, 장식 이미지, 작은 아이콘 전용 버튼, 전문 금융용어를 피한다.
- 판매자용과 고객용 화면을 시각적으로 구분하되 동일한 글자·버튼 규칙을 사용한다.

## 데이터와 기록

- 서버와 데이터베이스는 사용하지 않는다.
- 판매자 선택과 QR 생성 기록은 각 휴대폰의 로컬 저장소에만 보관한다.
- 기록 화면은 설정 메뉴 안에 두며 평상시 주 화면에는 노출하지 않는다.
- 오늘의 QR 생성 건수와 금액 합계를 자동 계산한다.
- 기록은 실제 입금 내역이 아니라 QR 생성 기준 예상 집계이다. 이 설명은 사용 안내서에만 기록하고 주 화면에는 표시하지 않는다.

## PWA

- 웹 앱 매니페스트, 192px·512px 아이콘, 서비스 워커를 제공한다.
- 삼성 인터넷과 Chrome에서 `홈 화면에 추가` 또는 `앱 설치`가 가능해야 한다.
- 설치 후 독립 실행 화면으로 열리고 기본 브라우저 주소창을 보이지 않는다.
- 판매자 금액 입력과 과거 로컬 기록 조회는 오프라인에서도 동작하게 캐시한다.
- 고객 송금 화면과 은행 앱 실행은 인터넷 연결이 필요하다.

## 오류 처리

- 설정 누락 시 누락 항목을 일반 사용자가 이해할 수 있는 한국어로 안내한다.
- QR 생성 실패 시 같은 금액으로 다시 시도할 수 있게 한다.
- 클립보드 복사 실패 시 계좌번호를 길게 눌러 복사하라는 안내를 표시한다.
- 은행 앱이 설치되지 않았거나 실행되지 않으면 계좌번호 복사 완료 상태와 수동 실행 안내를 유지한다.
- 잘못되거나 변조된 QR 주소는 송금 버튼 없이 오류 화면을 표시한다.

## 검증

- 금액 범위와 1,000원 단위 검증 테스트
- 숫자 키패드 입력·삭제·초기화 테스트
- 숫자와 한글 금액 표시 테스트
- 판매자 1·2 계좌 분리 테스트
- QR 생성 후 15초 자동 기록·초기화 테스트
- 주요 은행 순서와 `다른 은행 보기` 테스트
- 일반 은행 계좌 복사 및 앱 실행 실패 대체 흐름 테스트
- 토스 링크 생성과 실패 대체 흐름 테스트
- PWA 매니페스트와 빌드 결과 검증
- 삼성 안드로이드 실기기 2대에서 설치, QR 촬영, 은행 앱 이동, 토스 이동을 수동 확인

## 사용자 안내 산출물

- 개발자가 아닌 사용자를 위한 `처음 실행하기` 안내를 작성한다.
- 프로젝트 폴더에서 실행하는 정확한 PowerShell 명령을 제공한다.
- GitHub Pages 설정, 실제 계좌정보 등록, 배포 확인 과정을 단계별로 설명한다.
- 삼성 휴대폰에서 PWA를 홈 화면에 설치하는 절차를 설명한다.
- 행사 전 두 휴대폰에서 1,000원 시험 송금으로 계좌와 알림을 확인하는 체크리스트를 제공한다.

## 후속 단계로 유지할 기능

- 제품과 가격 설정 및 장바구니 합산
- 카카오페이 등 추가 결제 경로
- 인쇄용 고정 QR
- 설정 PIN
- 서버 기반 통합 매출 및 실제 입금 연동
- 태블릿 실기기 최적화
