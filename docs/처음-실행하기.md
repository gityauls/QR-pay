# 행사 QR 송금 처음 실행하기

이 문서는 컴퓨터에 익숙하지 않은 분도 앱을 준비하고, 두 분의 삼성 휴대폰에 설치하고, 행사장에서 바로 사용할 수 있도록 설명합니다.

중요: 실제 행사 전에 두 계좌를 정확히 등록하고 각각 1,000원 시험 송금을 꼭 해 보세요. 화면의 QR 생성 기록은 실제 입금 기록이 아닙니다. 실제 입금은 은행 문자나 은행 앱 알림으로 확인합니다.

## 1. 처음 한 번 준비하기

준비물은 다음과 같습니다.

- Windows 컴퓨터
- 인터넷 연결
- Node.js 22 이상
- GitHub 계정과 공개 저장소 `gityauls/QR-pay`
- 현재 입금받을 분의 정확한 은행명, 예금주명, 계좌번호
- 실제 사용할 삼성 휴대폰(현재 한 대만 있어도 시작 가능)

모든 PowerShell 명령은 반드시 `C:\QR-pay service` 폴더에서 실행해야 합니다. 이전에 `C:\Users\1`에서 명령을 실행해 `package.json`이나 `.env.example`을 찾지 못했던 이유가 바로 이것입니다.

PowerShell을 열고 아래 한 줄을 복사해 실행하세요.

```powershell
Set-Location -LiteralPath 'C:\QR-pay service'
```

현재 위치를 확인하려면 다음을 실행합니다.

```powershell
Get-Location
Get-ChildItem package.json, .env.example, run-dev.cmd
```

화면에 `C:\QR-pay service`와 세 파일이 표시되면 올바른 위치입니다.

## 2. 실제 계좌정보 입력하기

먼저 예제 설정 파일을 실제 사용용 파일로 복사합니다.

```powershell
Set-Location -LiteralPath 'C:\QR-pay service'
Copy-Item -LiteralPath '.env.example' -Destination '.env.local'
notepad '.env.local'
```

메모장이 열리면 아래 항목을 실제 정보로 바꿉니다.

```dotenv
VITE_SHOP_NAME=행사 판매점
VITE_USER1_LABEL=사용자 1
VITE_USER1_COLOR="#155E75"
VITE_USER1_BANK=실제 은행명
VITE_USER1_HOLDER=실제 예금주명
VITE_USER1_ACCOUNT=실제 계좌번호
VITE_USER2_LABEL=사용자 2
VITE_USER2_COLOR="#9A3412"
VITE_USER2_BANK=
VITE_USER2_HOLDER=
VITE_USER2_ACCOUNT=
```

예를 들어 계좌번호는 `123-456-789012`처럼 하이픈을 넣어도 됩니다. 장모님 계좌가 아직 준비되지 않았다면 사용자 2의 `BANK`, `HOLDER`, `ACCOUNT`는 비워 둡니다. 계좌가 준비되면 사용자 2의 다섯 항목을 모두 입력하며, 두 색상은 서로 달라야 합니다. 저장한 뒤 메모장을 닫습니다.

`.env.local`은 이 컴퓨터에서만 쓰며 GitHub에는 올라가지 않습니다. GitHub Pages용 정보는 4번에서 별도로 입력해야 합니다.

## 3. PC에서 시험 실행하기

가장 쉬운 방법은 탐색기에서 다음 파일을 두 번 클릭하는 것입니다.

`C:\QR-pay service\run-dev.cmd`

처음 한 번은 필요한 프로그램을 자동 설치하므로 조금 기다릴 수 있습니다. 검은 창에 다음 주소가 보이면 성공입니다.

`http://localhost:5173/`

브라우저 주소창에 이 주소를 입력합니다. 검은 창은 사용하는 동안 닫지 마세요.

PowerShell에서 직접 실행하려면 다음 명령만 사용합니다. 끝에 `\`를 붙이지 마세요.

```powershell
Set-Location -LiteralPath 'C:\QR-pay service'
npm.cmd install
npm.cmd run dev
```

PC 화면만 시험할 때는 `Local` 주소를 사용합니다. 같은 와이파이의 휴대폰으로 QR까지 시험하려면 검은 창에 표시된 `Network` 주소로 판매자 화면을 열어야 합니다. Windows 방화벽 질문이 나오면 개인 네트워크에서만 허용하세요. 가장 확실한 휴대폰 시험 방법은 4번의 GitHub Pages 배포 주소를 사용하는 것입니다.

## 4. GitHub Pages에 배포하기

이 단계는 인터넷에서 휴대폰으로 사용할 실제 주소를 만드는 과정입니다.

### 4-1. 일반 설정값 등록

1. GitHub에서 `gityauls/QR-pay` 저장소를 엽니다.
2. `Settings`를 누릅니다.
3. 왼쪽에서 `Secrets and variables`를 펼치고 `Actions`를 누릅니다.
4. `Variables` 탭에서 `New repository variable`을 눌러 아래 값을 하나씩 등록합니다.

| 이름 | 입력할 값 |
|---|---|
| `QR_PAY_SHOP_NAME` | 행사 또는 판매점 이름 |
| `QR_PAY_USER1_LABEL` | 사용자 1을 알아볼 이름 |
| `QR_PAY_USER1_COLOR` | `#155E75` |
| `QR_PAY_USER1_BANK` | 사용자 1의 실제 은행명 |
| `QR_PAY_USER2_LABEL` | 사용자 2 계좌가 준비된 뒤 등록 |
| `QR_PAY_USER2_COLOR` | 사용자 2 계좌가 준비된 뒤 `#9A3412` 등록 |
| `QR_PAY_USER2_BANK` | 사용자 2 계좌가 준비된 뒤 등록 |

은행명은 통장 첫 장에 적힌 그대로 씁니다. 예: `NH농협은행`, `서산농협`, `한우축협`, `신한`. 지역농협·축협 계좌도 앱이 알아서 구분하고, 토스는 `농협`으로 연결합니다.

### 4-2. 예금주와 계좌번호 등록

같은 화면의 `Secrets` 탭에서 `New repository secret`을 눌러 아래 네 값을 하나씩 등록합니다.

| 이름 | 입력할 값 |
|---|---|
| `QR_PAY_USER1_HOLDER` | 사용자 1의 실제 예금주명 |
| `QR_PAY_USER1_ACCOUNT` | 사용자 1의 실제 계좌번호 |
| `QR_PAY_USER2_HOLDER` | 사용자 2 계좌가 준비된 뒤 등록 |
| `QR_PAY_USER2_ACCOUNT` | 사용자 2 계좌가 준비된 뒤 등록 |

Secret에 넣어도 배포된 고객 화면에는 송금을 위해 계좌가 표시됩니다. 다만 공개 Git 파일과 커밋 기록에는 계좌번호가 남지 않습니다.

지금은 사용자 1만 쓴다면 사용자 2의 Variable과 Secret은 만들지 않습니다. 나중에 계좌가 준비되면 사용자 2의 다섯 값을 모두 등록하고 다시 배포합니다.

### 4-3. Pages 켜기

1. 저장소 `Settings → Pages`로 이동합니다.
2. `Build and deployment`의 `Source`를 `GitHub Actions`로 선택합니다.
3. 저장소의 `Actions` 탭에서 `Test and deploy QR Pay` 작업이 초록색 체크가 될 때까지 기다립니다.
4. `Settings → Pages`에 표시된 `https://gityauls.github.io/QR-pay/` 주소를 엽니다.

Actions가 빨간색이면 대부분 4-1 또는 4-2의 값이 빠졌거나 이름을 다르게 입력한 경우입니다.

## 5. 삼성 휴대폰에 앱으로 설치하기

두 휴대폰에서 각각 아래 작업을 합니다.

1. Chrome 또는 삼성 인터넷으로 GitHub Pages 주소를 엽니다.
2. 브라우저 메뉴 `⋮`를 누릅니다.
3. Chrome에서는 `홈 화면에 추가` 또는 `앱 설치`를 누릅니다.
4. 삼성 인터넷에서는 `현재 페이지 추가 → 홈 화면`을 누릅니다.
5. 홈 화면에 생긴 `QR 송금` 아이콘을 엽니다.
6. 판매자가 한 명이면 금액 입력 화면이 바로 열립니다. 두 명을 등록한 뒤에는 첫 휴대폰은 사용자 1, 두 번째 휴대폰은 사용자 2를 한 번 선택합니다.
7. 화면 위의 이름·은행명·전체 계좌번호가 그 휴대폰 주인과 일치하는지 확인합니다.

선택한 사용자는 휴대폰 안에만 저장됩니다. 브라우저 사용기록을 삭제하면 다시 선택해야 할 수 있습니다. 사용자를 바꾸려면 금액 화면의 `설정 → 받는 분 바꾸기`를 누릅니다.

## 6. 행사장에서 사용하는 순서

1. 홈 화면의 `QR 송금` 아이콘을 엽니다.
2. 화면 위의 받는 사람과 계좌번호를 확인합니다.
3. 판매 합계 금액을 입력합니다. 숫자판 위의 `+1만원`, `+5천원`, `+1천원` 버튼은 누를 때마다 금액이 더해집니다. 예: 14,000원은 `+1만원` 한 번, `+1천원` 네 번 또는 숫자판으로 `1`, `4`, `0`, `0`, `0`을 누릅니다. 잘못 눌렀으면 `전체 지우기`를 누릅니다.
4. 숫자 `14,000원`과 한글 `1만 4천원`이 모두 맞는지 확인합니다.
5. `QR 만들기`를 누릅니다.
6. 고객에게 QR을 보여 줍니다.
7. 고객은 카메라로 QR을 찍고 자기 은행 앱 버튼을 누릅니다.
8. 일반 은행은 복사된 계좌번호를 붙여넣고 금액을 직접 입력합니다. 토스는 계좌와 금액 자동 입력을 시도합니다. 아이폰에서는 토스만 앱이 자동으로 열리고, 다른 은행은 계좌번호만 복사되므로 고객이 은행 앱을 직접 엽니다.
9. 고객이 송금하기 전에 예금주와 금액을 다시 확인합니다.
10. 판매자는 자기 휴대폰의 은행 문자나 은행 앱 알림으로 실제 입금을 확인합니다.

QR 화면은 15초 뒤 자동으로 빈 금액 화면으로 돌아갑니다. 다음 손님 버튼을 누를 필요가 없습니다.

`설정`을 누르면 그 휴대폰에서 오늘 만든 QR 건수와 합계를 볼 수 있습니다. 이 숫자는 입금 확인 결과가 아니라 QR을 만든 기록입니다.

## 7. 행사 전 1,000원 시험 송금

실제 행사 전 현재 등록된 사용자마다 따로 시험합니다.

1. 사용자 1 휴대폰에서 `1000`을 입력해 QR을 만듭니다.
2. 다른 휴대폰으로 QR을 찍습니다.
3. 고객 화면의 은행·예금주·전체 계좌번호·1,000원이 모두 맞는지 확인합니다.
4. 자주 쓰는 일반 은행 버튼을 눌러 계좌번호가 복사되고 앱이 열리는지 확인합니다.
5. 1,000원을 실제 송금하고 사용자 1 휴대폰에 입금 문자 또는 알림이 오는지 확인합니다.
6. 사용자 2 계좌를 추가한 뒤에는 사용자 2도 같은 순서로 반복합니다.
7. 토스를 사용할 사람이 있다면 토스에서도 계좌와 금액이 맞는지 별도로 확인합니다.

하나라도 다르면 행사에서 사용하지 말고 설정값부터 바로잡으세요.

## 8. 문제가 생겼을 때

### `package.json`을 찾을 수 없다고 나옵니다

현재 위치가 잘못된 것입니다. 아래 명령을 먼저 실행한 뒤 다시 시작합니다.

```powershell
Set-Location -LiteralPath 'C:\QR-pay service'
npm.cmd run dev
```

### `.env.example`을 찾을 수 없다고 나옵니다

역시 `C:\Users\1` 같은 다른 폴더에서 실행한 경우입니다.

```powershell
Set-Location -LiteralPath 'C:\QR-pay service'
Copy-Item -LiteralPath '.env.example' -Destination '.env.local'
notepad '.env.local'
```

### `계좌 설정이 필요합니다`가 나옵니다

`.env.local`에서 사용자 1의 이름·색상·은행명·예금주·계좌번호를 모두 입력합니다. 사용자 2를 쓴다면 사용자 2의 다섯 항목도 모두 입력하고, 쓰지 않는다면 사용자 2의 은행명·예금주·계좌번호를 비웁니다. 저장한 뒤 실행 중인 검은 창에서 `Ctrl+C`를 눌러 종료하고 `run-dev.cmd`를 다시 실행합니다.

### 휴대폰에서 QR 주소에 접속할 수 없습니다

QR을 `localhost` 주소에서 만든 경우 휴대폰은 PC의 localhost에 접속할 수 없습니다. GitHub Pages 주소에서 앱을 열어 QR을 만드세요. 로컬 시험이라면 PC와 휴대폰을 같은 와이파이에 연결하고 `Network` 주소를 사용합니다.

### 은행 버튼을 눌렀는데 앱스토어가 열립니다

해당 은행 앱이 설치되지 않았거나 은행 앱의 실행 주소가 바뀐 경우입니다. 고객의 은행 앱을 직접 열고, 이미 복사된 계좌번호를 붙여넣어 송금하면 됩니다.

### 토스에 금액이 자동으로 들어가지 않습니다

토스 자동 입력 주소는 공식적으로 보장된 기능이 아닙니다. 고객 화면에 보이는 계좌와 금액을 확인하고, 복사된 계좌번호와 금액을 토스에 직접 입력합니다.

### 입금 알림이 오지 않습니다

이 앱은 입금을 감지하지 않습니다. 해당 은행의 입출금 알림이나 문자서비스가 켜져 있는지 은행 앱 또는 은행 창구에서 확인합니다.

### GitHub Actions가 빨간색으로 실패합니다

`Settings → Secrets and variables → Actions`에서 사용자 1의 6개 설정과 판매점 이름이 있는지 확인합니다. 사용자 2를 등록했다면 사용자 2의 다섯 값도 모두 있어야 합니다. 색상은 `#155E75`처럼 `#`을 포함한 6자리 형식이어야 하며, 계좌번호에는 숫자·공백·하이픈만 사용할 수 있습니다.

### 계좌나 예금주가 틀렸습니다

즉시 사용을 중단하세요. GitHub Variables/Secrets 값을 수정한 뒤 `Actions → Test and deploy QR Pay → Run workflow`로 다시 배포하고, 두 계좌 모두 1,000원 시험 송금을 다시 합니다.
