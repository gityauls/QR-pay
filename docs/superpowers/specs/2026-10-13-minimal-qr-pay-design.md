# 최소 QR 계좌송금 MVP 설계

## 목적

행사장에서 60대 판매자 두 분이 복잡한 메뉴 없이 입금받을 사람과 금액만 고른 뒤 QR을 보여준다. 고객은 QR을 촬영해 정확한 계좌와 금액을 확인하고 계좌번호를 복사한 다음, 자신이 쓰는 은행 앱에서 송금한다.

이 앱은 결제를 처리하거나 입금을 자동 확인하지 않는다. 돈은 고객 은행에서 판매자 계좌로 직접 이동하며, 판매자는 자기 휴대폰의 은행 입금 알림을 확인한다.

## 확정 범위

### 포함

- 판매자 `사용자 1`, `사용자 2` 중 한 명 선택
- 선택 결과를 휴대폰에 기억하고, 명시적으로 바꿀 때까지 유지
- 100원부터 500,000원까지 최종 금액 직접 입력
- 선택한 판매자 번호와 금액만 담긴 QR 생성
- 고객 화면에서 상호, 금액, 은행, 전체 예금주명, 계좌번호 표시
- 계좌번호 복사와 은행 앱에서 금액을 직접 입력하라는 안내
- 판매자가 `입금 확인 후 다음 손님`을 누르면 해당 기기에 시각·사용자·금액 저장
- 숨겨진 기록 화면에서 오늘 판매 건수, 합계, 개별 내역 확인
- GitHub Pages 자동 배포 설정

### 제외

- 상품·사진·장바구니·상품별 가격
- 토스 금액 자동 입력과 은행 앱 실행
- 서버, 데이터베이스, 로그인, 기기간 동기화
- 앱에서 계좌정보 수정
- 결제·입금 자동 확인
- 카카오페이, 현금영수증, 인쇄용 상품 QR

## 화면과 흐름

1. 앱을 처음 열면 `누가 받으시나요?` 아래에 사용자 두 명의 큰 버튼을 표시한다.
2. 사용자를 고르면 화면 위 고정 띠에 `사용자 1 계좌로 받는 중`처럼 현재 상태를 표시한다.
3. 큰 숫자 입력칸에 최종 금액을 입력하고 `QR 보여주기`를 누른다.
4. QR 화면에는 받는 사용자, 금액, 큰 QR, `입금 확인 후 다음 손님` 버튼을 표시한다.
5. 고객은 QR을 촬영해 `/pay/?u=1&a=45000` 같은 주소를 연다.
6. 고객 화면은 금액과 계좌정보를 크게 표시하고 계좌번호 복사 버튼을 제공한다.
7. 판매자가 실제 은행 알림을 확인한 뒤 다음 손님 버튼을 누르면 판매 기록을 저장하고 금액 입력 화면으로 돌아간다.

## 구조

- Vite + TypeScript 정적 다중 페이지 앱
- 판매자 화면: `/index.html`
- 고객 화면: `/pay/index.html`
- QR 생성: 브라우저 안에서 `qrcode` 패키지 사용
- 계좌 설정: Vite 빌드 환경변수에서 읽고 런타임에 검증
- 판매 기록과 현재 사용자: `localStorage`
- 배포: GitHub Actions가 테스트와 빌드를 통과한 결과만 GitHub Pages에 게시

계좌번호는 QR URL에 넣지 않는다. URL의 `u=1|2`를 배포된 설정에 매핑하므로 URL을 조작해도 설정에 없는 제3의 계좌로 바뀌지 않는다. 정적 웹의 특성상 고객에게 표시되는 은행·예금주·계좌번호는 배포된 브라우저 코드에서도 확인할 수 있으며 비밀정보로 취급할 수 없다.

## 오류 처리

- 계좌 설정이 빠졌으면 QR 생성 대신 `관리자에게 계좌 설정을 요청해 주세요`를 표시한다.
- 사용자 번호가 없거나 `1`, `2`가 아니면 고객 화면에서 송금을 진행하지 못하게 한다.
- 금액이 정수 또는 허용 범위가 아니면 QR 생성과 계좌 복사를 막는다.
- 클립보드 복사가 실패하면 선택 가능한 계좌번호와 `길게 눌러 복사하세요` 안내를 표시한다.
- 브라우저 저장소가 차단되면 결제 흐름은 계속 동작하되 기록 저장 실패를 명확히 알린다.

## 사용성과 시각 원칙

- 판매자 화면 본문 22px 이상, 금액 48px 이상, 주요 버튼 높이 72px 이상
- 고객 화면도 40대 이상을 기준으로 금액과 계좌정보를 크게 표시
- 색만으로 사용자를 구분하지 않고 번호·이름·문구를 함께 표시
- 한 화면에서 한 가지 작업만 수행
- 숨은 제스처, 작은 아이콘 버튼, 영어 전문용어를 사용하지 않음
- 모바일 360px 폭부터 가로·세로 화면 모두 지원

## 데이터와 보안

- 고객 개인정보를 수집하거나 외부로 전송하지 않음
- 판매 기록은 각 휴대폰에만 저장하며 다른 기기와 합쳐지지 않음
- 동적 HTML 삽입 없이 `textContent`와 DOM API만 사용
- 외부 분석·광고·폰트·스크립트를 사용하지 않음
- 저장소에는 실제 계좌번호를 커밋하지 않고 GitHub Actions 설정에서 빌드 시 주입
- 검색 엔진 노출을 줄이기 위해 고객 페이지에 `noindex, nofollow` 적용

## 검증 기준

- 사용자 1과 사용자 2의 QR이 각자 올바른 계좌 화면을 연다.
- QR URL에는 계좌번호와 예금주가 없다.
- 100원 미만, 500,000원 초과, 비정수 금액을 거부한다.
- 계좌 복사 버튼이 숫자 계좌번호를 복사한다.
- 입금 확인 버튼을 누른 판매만 해당 기기의 오늘 기록에 포함된다.
- 새로고침 후에도 선택 사용자와 판매 기록이 유지된다.
- 360px 모바일 화면에서 가로 스크롤 없이 주요 작업을 수행할 수 있다.
- 테스트와 프로덕션 빌드가 모두 성공해야 배포할 수 있다.
